01

Quick start

OwlMail listens for SMTP on localhost:1025 and serves the inbox on http://localhost:1080 by default.

  1. Point your application at OwlMail. 
    SMTP_HOST=localhost
SMTP_PORT=1025
SMTP_SECURE=false
  2. Send a message from your application, or run this smoke test if your curl build supports SMTP: 
    printf 'From: dev@example.test\r\nTo: inbox@example.test\r\nSubject: OwlMail test\r\n\r\nHello from OwlMail.\r\n' \
  | curl --url smtp://localhost:1025 \
      --mail-from dev@example.test \
      --mail-rcpt inbox@example.test \
      --upload-file -
  3. Open the inbox. New messages appear live through WebSocket updates.
Container networking: another container should use the OwlMail service name, not localhost. A host application connecting to Docker Desktop can continue to use the published port.

Web authentication defaults

With only a username, OwlMail generates a random 32-character password and prints it once to stderr at startup. With only a password, the username defaults to admin. Supplying neither value disables authentication; supplying both uses them unchanged. Generated passwords change after every restart, so configure both values when credentials must remain stable. Startup fails if the generated password cannot be written to stderr. Use Basic Auth only over localhost or HTTPS.

SMTP authentication and capacity: omitting both credentials selects NO AUTH, which permits unauthenticated delivery and accepts arbitrary PLAIN/LOGIN credentials for test clients. Setting both requires valid AUTH; setting only one fails startup. PLAIN/LOGIN is permitted without TLS for development compatibility by default. Enable -smtp-auth-require-tls with SMTP TLS to reject AUTH on cleartext connections while allowing it after STARTTLS and over SMTPS; anonymous NO AUTH delivery is unchanged, and missing TLS makes startup fail. Each SMTP/SMTPS connection defaults to 10-second read and write timeouts, configurable with -smtp-read-timeout and -smtp-write-timeout; a message is limited to 100 MiB by default (configurable with -smtp-max-message-mb) and 50 recipients by default (configurable with -smtp-max-recipients). One per-process limit of eight active DATA transactions is shared by SMTP, STARTTLS, and SMTPS; 0 is unlimited. Each replica enforces its own limit. At capacity the client receives retryable 451 4.3.2 temporary resource limit reached; try again later.
Outgoing relay security: use -outgoing-tls-mode starttls for mandatory STARTTLS or smtps for TLS from connection establishment. STARTTLS capability, handshake, certificate, or hostname failures stop delivery without a plaintext fallback. The MailDev-compatible -outgoing-secure alias means smtps. Credentials are never sent in plain mode. Certificate verification is on by default; -outgoing-insecure-skip-verify is an explicit unsafe opt-out.

04

Notifications and webhooks

Browser notifications

Notifications are off by default. Click Notifications off in the inbox header to request permission. Only new WebSocket messages received after enabling the preference create notifications; loading existing mail does not.

Server-side webhooks

Webhook forwarding runs even when no browser is open. Targets can filter mail, send custom JSON or text, add authentication headers and HMAC signatures, and retry transient failures.

Browser requirement: notifications need HTTPS or a trusted local origin such as http://localhost. If permission was denied, allow OwlMail in the browser's site settings first.

Open the local Webhook Configurator to build, import, validate, and download this JSON without sending configuration data to a server.

Minimal webhook configuration

{
  "version": 1,
  "targets": [
    {
      "name": "local-receiver",
      "url": "http://127.0.0.1:18080/owlmail"
    }
  ]
}
./owlmail -webhook-config ./webhooks.json

Omit both -webhook-config and OWLMAIL_WEBHOOK_CONFIG to keep forwarding disabled. Restart OwlMail after changing the file.

At most eight email delivery jobs run concurrently by default. When the limit is full, stored-mail event processing waits instead of creating more webhook goroutines. Set -webhook-max-concurrency 0 only for intentional unlimited concurrency.

06

Security checklist

  • Keep the default loopback binding for local-only development.
  • If exposed to a network, set both web credentials and SMTP credentials; terminate TLS as appropriate.
  • Captured messages can contain credentials, reset links, and personal data. Protect the storage directory and backups.
  • Use development or test messages only. Review recipients carefully before enabling outgoing relay or auto-relay.
  • Webhook targets receive email content. Use trusted HTTPS endpoints, keep tokens in environment variables, and verify HMAC signatures.
07

Troubleshooting

The application cannot connect to SMTP

Confirm host and port, check whether OwlMail is bound to the expected interface, and verify Docker port publishing. TLS must match on both sides.

The inbox is empty after restart

Set -mail-directory or OWLMAIL_MAIL_DIR. In Docker, mount a volume at /app/mail.

Live updates stopped

Refresh the page and check that proxies allow WebSocket upgrade requests to {{OWLMAIL_BASE_PATHNAME}}/api/v1/ws.

Browser notifications are blocked

Allow notifications in the browser's site settings, return to OwlMail, and click the notification button again. Confirm the page uses HTTPS or localhost.

A webhook receives no request

Check startup logs, target matching rules, and container networking. Inside a container, 127.0.0.1 points to OwlMail itself; use the receiver service name.

HTML looks different from a real mailbox

OwlMail previews captured HTML in an isolated frame. Email clients apply different CSS and security rules, so validate important templates in target clients too.

Web 认证默认策略

只配置用户名时，OwlMail 会生成 32 字符随机密码，并在启动时向 stderr 输出一次；只配置密码时，用户名默认为 admin。两项均不配置表示关闭认证，两项均配置则原样使用。自动密码会在每次重启后变化，需要稳定凭据时应同时配置两项；如果无法将自动生成的密码写入 stderr，OwlMail 会启动失败。Basic Auth 只应在 localhost 或 HTTPS 上使用。

SMTP 鉴权与容量：两项凭据都省略时使用 NO AUTH，允许不认证投递，也接受测试客户端提交的任意 PLAIN/LOGIN 凭据；同时设置两项后强制验证，只设置一项会启动失败。为兼容开发环境，默认允许在未启用 TLS 时使用 PLAIN/LOGIN。启用 SMTP TLS 并设置 -smtp-auth-require-tls 后，明文连接会拒绝 AUTH，STARTTLS 后及 SMTPS 仍可正常认证；NO AUTH 匿名投递不变，缺少 TLS 配置会启动失败。每个 SMTP/SMTPS 连接的读写超时默认均为 10 秒，可用 -smtp-read-timeout 与 -smtp-write-timeout 调整；单封邮件默认最大 100 MiB（可用 -smtp-max-message-mb 调整），默认最多 50 个收件人（可用 -smtp-max-recipients 调整）。普通 SMTP、STARTTLS 与 SMTPS 共用每进程 8 个活动 DATA 事务的默认上限；0 表示不限制，多副本各自执行上限。达到上限时客户端收到可重试的 451 4.3.2 temporary resource limit reached; try again later。

通知与 Webhook

浏览器通知

通知默认关闭。点击收件箱顶部的通知已关闭后，浏览器才会请求权限。只有启用后通过 WebSocket 实时到达的新邮件会通知，加载已有邮件不会通知。

服务端 Webhook

即使没有打开浏览器，Webhook 转发也会运行。目标支持过滤邮件、发送自定义 JSON 或文本、添加鉴权请求头与 HMAC 签名，并对临时故障进行有限重试。

浏览器要求：通知需要 HTTPS 或 http://localhost 等受信任的本地来源。如果曾拒绝权限，应先在浏览器的网站设置中允许 OwlMail。

打开本地 Webhook 配置生成器，可在不上传配置数据的情况下生成、导入、校验并下载 JSON。

最小 Webhook 配置

{
  "version": 1,
  "targets": [
    {
      "name": "local-receiver",
      "url": "http://127.0.0.1:18080/owlmail"
    }
  ]
}
./owlmail -webhook-config ./webhooks.json

同时省略 -webhook-config 和 OWLMAIL_WEBHOOK_CONFIG 时，转发保持关闭。修改文件后需要重启 OwlMail。

默认最多同时处理 8 个邮件投递任务。达到上限时，已持久化邮件的事件处理会等待，而不会继续创建 Webhook goroutine。仅在明确需要无限并发时设置 -webhook-max-concurrency 0。

安全检查清单

  • 仅用于本地开发时，保留默认的回环地址监听。
  • 暴露到网络时，同时设置 Web 和 SMTP 凭据，并按场景启用或终止 TLS。
  • 捕获的邮件可能包含凭据、重置链接和个人信息，请保护存储目录及备份。
  • 只处理开发或测试邮件；开启外发转发或自动转发前，请仔细检查收件人。
  • Webhook 目标会收到邮件内容；应使用可信 HTTPS 端点、通过环境变量保存 Token，并校验 HMAC 签名。
07

问题排查

应用无法连接 SMTP

确认主机和端口，检查 OwlMail 是否监听预期网卡，并核对 Docker 端口映射。客户端和服务端的 TLS 设置必须一致。

重启后收件箱为空

设置 -mail-directory 或 OWLMAIL_MAIL_DIR。在 Docker 中，需要把数据卷挂载到 /app/mail。

实时更新停止

刷新页面，并确认代理允许 {{OWLMAIL_BASE_PATHNAME}}/api/v1/ws 的 WebSocket 升级请求。

浏览器通知被阻止

先在浏览器的网站设置中允许通知，返回 OwlMail 后再次点击通知按钮，并确认页面使用 HTTPS 或 localhost。

Webhook 没有收到请求

检查启动日志、目标匹配规则和容器网络。容器内的 127.0.0.1 指向 OwlMail 自身，应使用接收器的服务名。

HTML 与真实邮箱显示不同

OwlMail 在隔离框架中预览捕获的 HTML。不同邮件客户端会应用不同的 CSS 和安全规则，重要模板仍应在目标客户端中验证。
