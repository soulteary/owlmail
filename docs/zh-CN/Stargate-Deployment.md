# Stargate 接入与运维约束

本文为部署预览。正常 OwlMail 二进制仍拒绝多人启动；doctor、Compose 校验或合成测试通过均不代表门禁解除。单机用户无需部署这些服务。

## 用户只需要登录

用户打开一个网址，通过 Stargate 登录后进入自己的个人箱，不创建 OwlMail 密码、不选择空间、不配置 SMTP。Warden 提供稳定身份，Stargate 认证并输出可信声明；Phorge 决定通知对象和内容权限；Gorge 沿用现有 SMTP 投递；OwlMail 维护路由并隔离读取。

使用 Warden 已有的 `REQUIRE_EXPLICIT_USER_ID=true`，响应包含 `user_id`。上游必须保证 ID 不随邮箱/电话变化且永不分配给另一人；邮箱哈希不具备此保证。OwlMail namespace 固定于部署，不能来自客户端。参见[身份契约](../en/Stargate-Identity-Contract.md)。

真实可信邮箱验证声明仍未验收，禁止固定注入 `X-Auth-Email-Verified: true`。目录 mail、密码、短信、TOTP 和通用 AMR 不能替代精确邮箱证据。上游升级后，旧 session 没有证据时仍按未验证处理。

默认选择 `explicit-history`：可信当前邮箱证据绑定未来投递，旧待认领历史继续隔离。仅当部署保证整个历史窗口内地址未被回收或重分配，才使用 `verified-email` 自动归并历史。

## 推荐配置与网络边界

管理员配置站点、固定 namespace、私有代理 peer、允许收件域、系统 SMTP 账号、证书路径和状态卷，限额和清理先使用已有有界默认值。[容器示例](../../examples/multiuser/README.zh-CN.md) 是预览布局，不是可运行多人生产服务。

代理先剥除外部身份头，仅复制 Stargate 成功认证返回的白名单头。认证缺失、失败、超时不转发受保护请求。API 认证失败返回 401，避免 fetch 跟随跳转后得到成功 HTML；页面导航可正常跳转登录。后端 Web 不公开，同网段其他容器也须限制访问。可信 CIDR 不等于进程认证，X-Forwarded-For 不决定可信 peer。跨不可信网络时增加传输保护。

默认使用可靠本地文件系统。同一状态卷内分开存放邮件和权威控制库，控制库必须在邮件目录之外。配置、账号和密钥只读挂载且允许运行 UID 读取，不能以全局可读修复 UID 映射问题。

## SMTP 配置与凭据轮换

按发送系统配置账号，限制 namespace 和收件域，验证服务端证书和主机名。Gorge 无需新适配器或逐用户密码。SMTP envelope RCPT 决定投递目标，正文头不授予读取权限。被盗系统账号仍可在允许范围注入垃圾邮件，因此保留持久配额和待认领清理。

独立捕获域只有在通知地址映射与可信登录地址一致时才适用；不能只改 SMTP 域名。捕获失败不回退到真实外部收件人。Phorge 负责邮件业务内容是否应交付给目标用户。

账号文件在启动时加载，编辑文件不等于运行中撤销。轮换步骤：新增账号并暂留旧账号 → 受控重启 → 更新 Gorge 既有 SMTP 配置 → 用合成内容验证目标入箱 → 禁用旧账号并再次重启 → 验证旧认证拒绝、新投递成功。

紧急撤销先停止/限制 SMTP 入口并关闭活动连接，再禁用账号和重启，确认旧认证失败后恢复入口。不要承诺改文件会取消已进入 DATA 的事务；保留已接受数据并明确持久成功边界。断线重试可能重复，不用不可信 Message-ID 做全局去重。凭据不进入普通日志。

## 地址变更和恢复

同一稳定 ID 改邮箱不迁移个人箱。旧邮箱从声明消失不自动释放旧路由。地址交给另一个人前，在发送边界阻断该地址并暂停相关投递，保留旧 owner 的历史。不能用临时 SQL 修改在线控制库或自动覆盖绑定。

使用本地 [离线收件路由流程](Recipient-Route-Operations.md) 进行只读检查、精确计划、带审计的阻断与未来投递改绑。执行要求停止全部写入者、匹配 route ID/revision 和确认值；存在相关待恢复任务时拒绝。误阻断可按相同检查明确恢复至原 owner。目标必须是已有个人箱，不转移历史邮件，不提供在线管理接口，也不解除多人门禁或替代真实身份验收。

`owlmail doctor` 只做离线只读检查，不证明代理隔离、网络可达、可写存储、身份契约或实际通知成功。readiness 只表达本实例状态；身份不可验证则拒绝读取，不用无关上游故障触发重启或丢弃安全接受的投递。

邮件、权威控制库和配置必须来自一致恢复点，证书和密钥单独保护并关联版本。停写快照或采用已验证的协调机制；只复制活跃 SQLite 主文件不构成备份。离线恢复检查通过后再开放入口。控制库丢失必须恢复，不能从邮件索引重建归属。

审计绑定、冲突、重分配、迁移、轮换和恢复；不记录正文、验证码、密码、Cookie、Authorization 或原始身份头，不把任意用户/地址作为指标 label。已经下载的内容无法追溯撤回。
